# 第 10 小节：开发优惠券模板结束、增加发行量等功能

## 新手先读

本节是在“创建模板”之后补齐模板管理能力。重点不是新增了多少接口，而是理解模板生命周期：创建后可以查询、增加发行量，也可以提前结束。

如果你对并发更新库存不熟，先记住一个核心原则：不要先查库存再在 Java 里计算后更新，这样并发下容易丢数据；更可靠的做法是让数据库用一条 `update stock = stock + ?` 完成原子更新。

## 5. 分页查询模板

Service 代码：

```java
LambdaQueryWrapper<CouponTemplateDO> queryWrapper = Wrappers.lambdaQuery(CouponTemplateDO.class)
        .eq(CouponTemplateDO::getShopNumber, UserContext.getShopNumber())
        .like(StrUtil.isNotBlank(requestParam.getName()), CouponTemplateDO::getName, requestParam.getName())
        .like(StrUtil.isNotBlank(requestParam.getGoods()), CouponTemplateDO::getGoods, requestParam.getGoods())
        .eq(Objects.nonNull(requestParam.getType()), CouponTemplateDO::getType, requestParam.getType())
        .eq(Objects.nonNull(requestParam.getTarget()), CouponTemplateDO::getTarget, requestParam.getTarget());

IPage<CouponTemplateDO> selectPage = couponTemplateMapper.selectPage(requestParam, queryWrapper);
return selectPage.convert(each -> BeanUtil.toBean(each, CouponTemplatePageQueryRespDTO.class));
```

关键点：

- 必须带 `shopNumber`，防止查询到别的店铺数据。
- 查询条件按用户输入动态拼接。
- `selectPage.convert` 把 DO 转成响应 DTO。

```java
LambdaQueryWrapper<CouponTemplateDO> queryWrapper = Wrappers.lambdaQuery(CouponTemplateDO.class)

return BeanUtil.toBean(couponTemplateDO, CouponTemplateQueryRespDTO.class);
```

详情查询同样带 `shopNumber`，不是只按 `id` 查询。这是防横向越权的基本要求。

## 7. 数据横向越权

横向越权是指用户操作了不属于自己的数据。

例子：

```text
张三店铺创建了优惠券 ID=1001
李四通过猜测或抓包拿到 ID=1001
李四调用结束接口把张三的优惠券结束
```

防御方式：任何操作都同时校验业务 ID 和当前用户/店铺归属。

```java
Wrappers.lambdaQuery(CouponTemplateDO.class)
        .eq(CouponTemplateDO::getShopNumber, UserContext.getShopNumber())
        .eq(CouponTemplateDO::getId, couponTemplateId);
```

如果查不到，不能简单认为“数据不存在”，还要意识到可能是越权访问。

## 8. 结束优惠券模板

核心步骤：

1. 查询当前店铺下的模板。
2. 模板不存在则抛异常。
3. 模板不是生效中则抛异常。
4. 记录原始数据到操作日志上下文。
5. 更新数据库状态为已结束。
6. 更新 Redis 缓存中的 `status`。

关键代码：

```java
if (couponTemplateDO == null) {
    throw new ClientException("优惠券模板异常，请检查操作是否正确...");
}

if (ObjectUtil.notEqual(couponTemplateDO.getStatus(), CouponTemplateStatusEnum.ACTIVE.getStatus())) {
    throw new ClientException("优惠券模板已结束");
}

CouponTemplateDO updateCouponTemplateDO = CouponTemplateDO.builder()
        .status(CouponTemplateStatusEnum.ENDED.getStatus())
        .build();

Wrapper<CouponTemplateDO> updateWrapper = Wrappers.lambdaUpdate(CouponTemplateDO.class)
        .eq(CouponTemplateDO::getId, couponTemplateDO.getId())
        .eq(CouponTemplateDO::getShopNumber, UserContext.getShopNumber());

couponTemplateMapper.update(updateCouponTemplateDO, updateWrapper);
```

状态校验能防止用户重复结束同一张券，避免重复操作日志和无意义更新。

## 9. 增加发行量

核心步骤：

1. 校验模板归属。
2. 校验模板状态必须生效中。
3. 记录原始数据。
4. 执行数据库库存递增。
5. 更新 Redis Hash 中的 `stock`。

关键代码：

```java
int increased = couponTemplateMapper.increaseNumberCouponTemplate(
        UserContext.getShopNumber(),
        requestParam.getCouponTemplateId(),
        requestParam.getNumber()
);
if (!SqlHelper.retBool(increased)) {
    throw new ServiceException("优惠券模板增加发行量失败");
}

String couponTemplateCacheKey = String.format(MerchantAdminRedisConstant.COUPON_TEMPLATE_KEY, requestParam.getCouponTemplateId());
stringRedisTemplate.opsForHash().increment(couponTemplateCacheKey, "stock", requestParam.getNumber());
```

Mapper XML 中的核心 SQL 是：

```sql
UPDATE t_coupon_template
SET stock = stock + #{number}
WHERE shop_number = #{shopNumber}
  AND id = #{couponTemplateId}
```

这种写法不会先查出库存再回写，而是让 MySQL 在更新时基于最新行值递增。

## 10. 并发增加库存为什么不丢失

错误做法：

```text
线程 A 读 stock=10
线程 B 读 stock=10
线程 A 写 stock=20
线程 B 写 stock=20
最终 stock=20，丢失一次更新
```

本节做法：

```sql
UPDATE t_coupon_template SET stock = stock + 10 WHERE ...
```

MySQL 更新同一行时会加行排他锁。多个并发更新会排队执行：

```text
stock=10
线程 A: stock = stock + 10 -> 20
线程 B: stock = stock + 10 -> 30
```

最终结果正确。

## 11. Spring Boot / 框架语法补充

### 11.1 `@GetMapping`

用于查询接口：

```java
@GetMapping("/api/merchant-admin/coupon-template/find")
public Result<CouponTemplateQueryRespDTO> findCouponTemplate(String couponTemplateId) {
}
```

GET 请求参数通常来自 query string：

```text
/api/merchant-admin/coupon-template/find?couponTemplateId=1001
```

### 11.2 MyBatis-Plus `LambdaQueryWrapper`

普通字符串字段写法：

```java
queryWrapper.eq("shop_number", shopNumber);
```

Lambda 写法：

```java
Wrappers.lambdaQuery(CouponTemplateDO.class)
        .eq(CouponTemplateDO::getShopNumber, shopNumber);
```

好处：字段重命名时编译器能发现问题，不容易写错列名。

### 11.3 条件拼接

```java
.like(StrUtil.isNotBlank(requestParam.getName()), CouponTemplateDO::getName, requestParam.getName())
```

第一个参数是条件开关：

- `true`：拼接 `LIKE name` 条件。
- `false`：忽略这一项。

### 11.4 `IPage`

`IPage<T>` 是 MyBatis-Plus 的分页结果接口，通常包含：

- 当前页。
- 每页大小。
- 总记录数。
- 当前页数据列表。

响应类型：

```java
Result<IPage<CouponTemplatePageQueryRespDTO>>
```

表示接口返回统一 `Result`，里面的 `data` 是分页结果。

### 11.5 `SqlHelper.retBool`

```java
SqlHelper.retBool(increased)
```

把数据库影响行数转换成布尔值：

- `increased > 0`：成功。
- `increased == 0`：失败。

### 11.6 Redis Hash `increment`

```java
stringRedisTemplate.opsForHash().increment(couponTemplateCacheKey, "stock", requestParam.getNumber());
```

含义：把 Redis Hash 中 `stock` 字段增加指定数量。

类似 Redis 命令：

```text
HINCRBY key stock number
```
