# 第 09 小节：基于注解实现分布式锁防重复提交

## 新手先读

本节要解决的是重复点击、接口重试、网关转发等场景下的重复提交。新手可以先把分布式锁理解成“多台机器都能看见的一把锁”，而不是只能在当前 JVM 里生效的 `synchronized`。

阅读顺序建议先看注解怎么用，再看 AOP 怎么拦截，最后看 Redisson 怎么加锁。AOP 语法刚开始不熟没关系，先理解它的作用：在业务方法执行前后自动插入一段通用逻辑。

## 2. 教程核心内容提炼

教程围绕“商家重复点击创建优惠券按钮”展开：

- 前端按钮未禁用、网络延迟、用户刷新页面都可能导致重复提交。
- 单机锁只能保护单个 JVM，不能保护多实例部署。
- 分布式锁可以让多个服务实例竞争同一把锁。
- 防重复提交逻辑不应写死在业务方法里，应抽象为注解组件。
- 本节通过自定义注解、Spring AOP、Redisson 实现通用防重复提交组件。

## 4. 业务背景

创建优惠券模板是典型表单提交操作。重复提交可能导致：

- 同一个商家创建多张完全相同的券。
- Redis 缓存重复预热。
- 操作日志重复记录。
- 后续发行、分发、领取链路产生脏数据。

前端禁用按钮能缓解问题，但后端仍必须兜底，因为请求可能来自浏览器刷新、接口重试、脚本调用或多端并发。

## 5. 为什么不用本地锁

本地锁示例：

```java
public synchronized void createCouponTemplate() {
    // 创建优惠券模板
}
```

或：

```java
private final ReentrantLock lock = new ReentrantLock();

public void createCouponTemplate() {
    lock.lock();
    try {
        // 创建优惠券模板
    } finally {
        lock.unlock();
    }
}
```

问题：

- 只在当前 JVM 内有效。
- 多台服务器部署时，每台机器都有自己的锁。
- 无法阻止不同实例同时处理同一个重复请求。
- 如果锁粒度太粗，还会把不同用户、不同参数的请求串行化。

因此要用所有实例都能访问的共享锁，本节使用 Redis/Redisson。

## 6. 自定义注解

文件：

```text
framework/src/main/java/com/nageoffer/onecoupon/framework/idempotent/NoDuplicateSubmit.java
```

代码：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NoDuplicateSubmit {

    String message() default "您操作太快，请稍后再试";
}
```

解释：

- `@Target(ElementType.METHOD)`：这个注解只能标在方法上。
- `@Retention(RetentionPolicy.RUNTIME)`：运行时仍然保留，AOP 可以通过反射读取。
- `message`：重复提交时返回给用户的提示。

业务使用：

```java
@NoDuplicateSubmit
@PostMapping("/api/merchant-admin/coupon-template/create")
public Result<Void> createCouponTemplate(@RequestBody CouponTemplateSaveReqDTO requestParam) {
    couponTemplateService.createCouponTemplate(requestParam);
    return Results.success();
}
```

```java
@Around("@annotation(com.nageoffer.onecoupon.framework.idempotent.NoDuplicateSubmit)")
public Object noDuplicateSubmit(ProceedingJoinPoint joinPoint) throws Throwable {

}
```

含义：拦截所有标注了 `@NoDuplicateSubmit` 的方法。

## 8. 锁 Key 设计

代码：

```java
String lockKey = String.format(
        "no-duplicate-submit:path:%s:currentUserId:%s:md5:%s",
        getServletPath(),
        getCurrentUserId(),
        calcArgsMD5(joinPoint)
);
```

Key 由三部分组成：

| 组成 | 作用 |
| --- | --- |
| 请求路径 | 区分不同接口 |
| 当前用户 ID | 区分不同用户 |
| 参数 MD5 | 区分同一用户不同请求参数 |

这样可以避免两个问题：

- 不同用户创建优惠券互相阻塞。
- 同一用户提交不同优惠券参数互相阻塞。

## 9. Redisson 分布式锁逻辑

核心代码：

```java
RLock lock = redissonClient.getLock(lockKey);

if (!lock.tryLock()) {
    throw new ClientException(noDuplicateSubmit.message());
}

Object result;
try {
    result = joinPoint.proceed();
} finally {
    lock.unlock();
}
return result;
```

解释：

- `getLock(lockKey)`：获取一把 Redis 分布式锁对象。
- `tryLock()`：尝试加锁，失败说明已有相同请求正在执行。
- `joinPoint.proceed()`：继续执行原业务方法。
- `finally unlock()`：无论业务成功还是异常，都释放锁。

## 10. 自动装配

文件：

```text
framework/src/main/java/.../config/IdempotentConfiguration.java
```

代码：

```java
public class IdempotentConfiguration {

    @Bean
    public NoDuplicateSubmitAspect noDuplicateSubmitAspect(RedissonClient redissonClient) {
        return new NoDuplicateSubmitAspect(redissonClient);
    }
}
```

并在自动装配文件中加入：

```text
com.nageoffer.onecoupon.framework.config.IdempotentConfiguration
```

业务模块引入 `framework` 后，就能自动注册防重复提交切面。

## 11. Spring Boot / 框架语法补充

### 11.1 自定义注解

Java 注解定义格式：

```java
public @interface DemoAnnotation {
    String value() default "";
}
```

使用：

```java
@DemoAnnotation("hello")
public void test() {
}
```

本节的 `@NoDuplicateSubmit` 就是自定义注解。

### 11.2 `@Aspect`

`@Aspect` 表示当前类是切面类，可以定义方法拦截逻辑。

最小示例：

```java
@Aspect
public class DemoAspect {
    @Around("@annotation(DemoAnnotation)")
    public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
        System.out.println("方法执行前");
        Object result = joinPoint.proceed();
        System.out.println("方法执行后");
        return result;
    }
}
```

### 11.3 `@Around`

`@Around` 是环绕通知，可以在目标方法执行前后都加入逻辑。

本节用它实现：

```text
加锁 -> 执行业务方法 -> 解锁
```

### 11.4 `ProceedingJoinPoint`

`ProceedingJoinPoint` 表示被拦截的方法调用。

常用方法：

```java
joinPoint.getArgs();     // 获取方法参数
joinPoint.getSignature();// 获取方法签名
joinPoint.proceed();     // 执行原方法
```

### 11.5 `RequestContextHolder`

它可以获取当前请求上下文：

```java
ServletRequestAttributes sra =
        (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
String path = sra.getRequest().getServletPath();
```

本节用它把请求路径放进锁 Key。

### 11.6 Redisson `RLock`

`RLock` 是 Redisson 提供的分布式锁接口，使用体验类似 Java 本地锁，但底层基于 Redis。

```java
RLock lock = redissonClient.getLock("lock-key");
if (lock.tryLock()) {
    try {
        // protected code
    } finally {
        lock.unlock();
    }
}
```
