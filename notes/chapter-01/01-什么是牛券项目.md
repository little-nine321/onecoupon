# 第 01 小节：什么是牛券项目？

## 新手先读

本节只需要建立项目全局印象，不需要理解所有技术细节。你可以先把“优惠券模板”理解成优惠券规则，把“用户优惠券”理解成某个用户真正拥有的一张券。

阅读时重点关注项目要解决的业务问题：商家怎么创建券，平台怎么发券，用户怎么领券，用券时系统怎么判断是否可用。后面出现的分库分表、缓存、消息队列，都是为了让这些业务在高并发和大数据量下仍然稳定。

- 项目不是单一 CRUD，而是覆盖后台管理、批量分发、领取秒杀、预约提醒、核销退还、结算搜索等链路。

## 3. 项目业务主线

优惠券系统可以按角色拆成两条主线。

商家/运营侧：

```text
创建优惠券模板
  -> 设置优惠规则、库存、有效期、领取限制
  -> 创建批量发券任务
  -> 定时或立即分发给用户
  -> 查看任务结果和失败记录
```

用户侧：

```text
查询可领券
  -> 领取/兑换/秒杀优惠券
  -> 预约开抢提醒
  -> 下单时选择优惠券
  -> 锁定优惠券
  -> 支付成功核销，失败退还
```

结算侧：

```text
订单金额 + 用户券列表
  -> 判断可用券和不可用原因
  -> 计算优惠金额
  -> 返回最终抵扣结果
```

## 4. 项目技术架构

项目最终包含这些主要服务：

| 服务 | 作用 |
| --- | --- |
| `gateway` | 统一入口和路由 |
| `merchant-admin` | 商家后台，管理模板和发券任务 |
| `distribution` | 批量分发用户券 |
| `engine` | 用户券查询、领取、预约、核销 |
| `settlement` | 结算时计算优惠 |
| `search` | 搜索优惠券模板 |
| `framework` | 公共能力模块 |

从业务复杂度看，核心不是“服务很多”，而是这些服务通过数据库、Redis、MQ、定时任务形成了完整链路。

## 5. 新概念解释

### 5.1 优惠券模板

优惠券模板是“券的定义”，不是用户实际拥有的券。

例如：

```text
满 100 减 20
有效期：2026-06-01 到 2026-06-30
发行量：10000
每人限领：1
```

这类信息属于模板。

### 5.2 用户优惠券

用户优惠券是模板发放给某个用户之后生成的实例。

例如：

```text
用户 10001 拥有模板 20001 的一张券
状态：未使用
领取时间：2026-06-09 18:00:00
```

同一个模板可以对应很多张用户券。

### 5.3 批量分发

批量分发是后台创建任务，把某个模板的券发给一批用户。项目里会涉及 Excel 解析、任务状态、MQ 消费、失败记录和消息通知。

### 5.4 秒杀领取

秒杀领取是用户主动抢券。它和批量分发最大的区别是并发冲击大，需要 Redis、库存原子扣减、防重复领取和异步落库。

### 5.5 结算

结算不是简单查询用户有哪些券，而是要判断订单金额、券门槛、券类型、有效期、使用范围等规则，最终给出可用券、不可用券和优惠金额。
