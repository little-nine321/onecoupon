# 第 02 小节：如何学习牛券项目？

## 新手先读

本节的价值是帮你确定学习顺序。不要按“先把所有中间件学完再看项目”的方式推进，那样很容易卡住。更建议先跟着业务流程读代码，遇到 Redis、RocketMQ、ShardingSphere 等技术时，再回到对应小节补概念。

如果你 Spring Boot 还不熟，先保证能看懂 Controller、Service、Mapper 三层分别做什么。高级框架语法可以边读边补，不需要一开始全部掌握。

## 1. 本节目标

本节重点不是业务实现，而是建立正确的学习方式：

- 使用 Git 分支学习项目演进。
- 不要只看最终代码，要看每个功能从前置分支到目标分支改了什么。
- 先跑通环境，再深入源码。
- 学习顺序按业务链路推进。

教程路径：

```text
D:\study\java\oneCoupon\第①章节：项目背景和规范\《牛券oneCoupon优惠券系统设计》第02小节：如何学习牛券项目？.html
```

对应分支：无固定功能分支。

## 2. 教程核心内容提炼

教程强调：

- 项目应通过 Git Clone 获取，而不是下载压缩包。
- 学习时应切换到指定功能分支，观察对应阶段的提交记录。
- `main` 分支会持续修复和优化，提交记录不一定适合逐步学习。
- 中间件依赖较多，先跑通服务比先深挖部署更重要。
- 代码不应上传到开放平台，需要尊重作者版权和项目权限。

## 3. 推荐学习方法

### 3.1 先看全局，再看单节

推荐顺序：

```text
00-项目整体架构.md
  -> 01-章节索引与分支映射.md
  -> 第 2 章后台管理服务
  -> 第 3 章分发与引擎服务
  -> 第 4 章结算服务
  -> 第 5 章面试总结
```

第 1 章是地图，第 2-4 章才是代码主线。

### 3.2 每一节按 diff 学

每个功能小节建议固定执行：

```bash
git diff 前置分支..目标分支 --stat
git diff 前置分支..目标分支 -- 模块路径
git show 目标分支:关键文件路径
```

这样能回答：

- 本节新增了哪些类？
- 哪些接口发生变化？
- 哪些配置发生变化？
- 是否新增表、缓存 Key、MQ Topic、定时任务？

### 3.3 不建议直接切当前工作区分支

当前仓库已有未提交改动，直接切分支可能带来冲突。

推荐方式：

```bash
git worktree add D:\study\java\oneCoupon\worktrees\onecoupon-study origin/main
```

之后在 `worktrees\onecoupon-study` 里自由切换教学分支。

## 4. 新概念解释

### 4.1 功能分支学习法

功能分支学习法不是看最终答案，而是看“从没有到有”的过程。

例如第 06 小节：

```text
前置分支：origin/20240708_init-code_ding.ma
目标分支：origin/20240814_dev_create-template_chain_ding.ma
```

你要看的不是目标分支所有代码，而是两个分支之间为了“创建优惠券模板”新增和修改了什么。

### 4.2 `git diff --stat`

`git diff --stat` 用来先看变更规模。

示例：

```bash
git diff origin/20240708_init-code_ding.ma..origin/20240814_dev_create-template_chain_ding.ma --stat
```

你可以先判断：

- 是改了几十个文件，还是只改了几处？
- 主要集中在哪个模块？
- 有没有配置、SQL、测试、文档变化？

### 4.3 `git show 分支:文件`

这个命令可以不切换分支，直接查看某个分支上的文件。

示例：

```bash
git show origin/main:pom.xml
```

这对当前工作区有未提交改动时特别有用。

## 6. 面试点

- 为什么学习项目时要看 Git 分支，而不是只看最终代码？
- 怎么通过 Git diff 快速定位某个功能的核心改动？
- 如果当前工作区有未提交改动，如何安全查看其他分支代码？
- 多模块项目学习时，为什么要先看根 `pom.xml`？

## 7. 学习检查清单

- 能列出后续学习的主线顺序。
- 能使用 `git diff A..B --stat` 看功能变更范围。
- 能使用 `git show branch:path` 查看指定分支文件。
- 知道当前项目不适合在有本地改动时频繁直接切分支。
