# 第 04 小节：依赖中间件与公有云使用讲解

## 新手先读

本节会出现很多中间件名称，新手容易觉得信息量太大。先记住每个组件的最小作用即可：MySQL 存业务数据，Redis 做缓存和高并发控制，Nacos 管配置和服务发现，RocketMQ 做异步消息，XXL-Job 做定时任务，Canal 监听数据库变更。

第一次搭环境时不要同时验证所有功能。建议先能启动基础服务和一个 Spring Boot 模块，再逐步补 Redis、RocketMQ、XXL-Job 等依赖。

## 1. 本节目标

本节目标是理解项目依赖哪些中间件，以及这些中间件在业务链路中解决什么问题。

对应分支：无固定功能分支，建议结合各模块 `application.yaml` 阅读。

## 2. 教程核心内容提炼

教程主要说明：

- 项目依赖 Redis、Nacos、RocketMQ、MySQL 等中间件。
- 为了降低学习门槛，部分强依赖中间件可以使用公有云版本。
- MySQL 不建议共用公有云实例，避免多人数据互相污染。
- 启动服务时需要通过 VM options 覆盖 Redis、RocketMQ、Nacos 等连接配置。
- `unique-name` 和 Redis key 前缀用于避免多人共用环境时互相影响。

注意：本笔记不复刻教程中的具体账号密码。需要连接信息时请回到原教程查看，并避免把凭据提交到仓库。

## 4. 为什么需要这些中间件

### 4.1 MySQL

MySQL 保存最终业务事实，例如：

- 优惠券模板。
- 发券任务。
- 用户优惠券。
- 结算规则。
- 任务失败记录。

即使 Redis 和 MQ 参与流程，最终仍要通过 MySQL 保证数据可追溯。

### 4.2 Redis

Redis 解决高并发读写和短期状态控制问题。

典型场景：

```text
用户查询模板 -> 先查 Redis 缓存
秒杀抢券 -> Redis 原子扣减库存
防重复提交 -> Redisson 分布式锁
预约提醒 -> Bitmap 记录某个时间点是否已提醒
```

### 4.3 Nacos

Nacos 负责服务注册发现。微服务不是写死地址互相调用，而是服务启动后注册到 Nacos，调用方通过服务名发现实例。

示例：

```text
engine 服务启动 -> 注册到 Nacos
gateway 收到请求 -> 根据路由转发到 engine 服务实例
```

### 4.4 RocketMQ

RocketMQ 负责把同步流程拆成异步流程。

典型场景：

```text
创建优惠券模板
  -> 发送延迟消息
  -> 到期后自动关闭模板

创建发券任务
  -> 发送任务执行消息
  -> distribution 消费并批量发券

用户预约提醒
  -> 发送延迟提醒消息
  -> 到时间后推送提醒
```

### 4.5 XXL-Job

XXL-Job 适合做定时调度，例如到某个时间点触发发券任务。它和 RocketMQ 的区别是：

- XXL-Job 更像“调度器”，按时间触发任务。
- RocketMQ 更像“事件管道”，负责异步传递消息。

## 5. VM Options 配置理解

教程中要求在 IDE 启动配置中添加 VM options。它们大致分为几类：

```text
-Dunique-name=你的唯一标识
-Dframework.cache.redis.prefix=你的Redis前缀
-Dspring.data.redis.host=Redis地址
-Dspring.data.redis.port=Redis端口
-Dspring.data.redis.password=Redis密码
-Drocketmq.name-server=RocketMQ地址
-Dspring.cloud.nacos.discovery.server-addr=Nacos地址
```

### 5.1 `unique-name`

共用 Nacos 或 RocketMQ 时，如果所有人的服务名、消费者组完全一致，可能出现互相调用或互相消费消息的问题。

`unique-name` 用于给服务实例、消费者组或相关资源加个人标识，降低冲突概率。

### 5.2 Redis 前缀

多人共用 Redis 时，如果都写同一个 Key，例如：

```text
coupon_template:10001
```

就会互相覆盖。加前缀后变成：

```text
你的前缀:coupon_template:10001
```

这样每个人的数据空间相对隔离。

## 6. 本地 MySQL 建议

教程建议 MySQL 本地安装或本地 Docker 启动，原因是数据库业务数据强依赖个人调试过程。

学习时要重点关注：

- 表结构是否与当前分支匹配。
- 当前分支是否新增字段或新增表。
- 分库分表章节是否需要初始化多个库表。
- 运行前是否已经执行对应 SQL。

## 8. 常见问题

### 8.1 服务启动失败

优先检查：

- MySQL 是否启动。
- Redis 地址、端口、密码是否正确。
- Nacos 是否可访问。
- RocketMQ name server 是否正确。
- 当前分支配置是否和教程对应。

### 8.2 服务注册错乱

如果使用公有云 Nacos，需要确保 `unique-name` 不和别人重复。

### 8.3 Redis 数据互相污染

确保设置了个人 Redis key 前缀，并且不要在笔记或代码中硬编码他人的前缀。

### 8.4 MQ 消息被别人消费

检查消费者组是否带了个人唯一标识。共用 RocketMQ 时，这是高频问题。
