# 第 21 小节：优惠券分发失败记录深分页优化

## 新手先读

本节解决的是运营查看失败记录时“翻到很后面的页会越来越慢”的问题。深分页不是业务错误，而是数据库执行 `limit offset, size` 时需要跳过大量记录导致的性能问题。

新手先记住替代思路：不要告诉数据库“跳过前面一百万条”，而是告诉数据库“从上一页最后一条 ID 后面继续查”。这就是游标分页或书签分页的核心。

## 2. 教程核心内容提炼

第 20 小节会把发券失败的用户写入 `t_coupon_task_fail`。如果一个批量任务有几十万用户，失败记录也可能很多。

任务结束时，需要把失败记录导出成 Excel。如果直接一次性查询全部失败记录，会有两个问题：

- 数据库一次返回太多行，查询慢。
- Java 内存一次保存太多对象，容易造成内存压力。

所以本节采用游标分页：

```sql
SELECT *
FROM t_coupon_task_fail
WHERE batch_id = ?
  AND id > ?
LIMIT 5000;
```

每次只查 5000 条，处理完后用本批最大 ID 作为下一批起点。

## 3. 传统深分页的问题

传统分页常见写法：

```sql
SELECT *
FROM t_coupon_task_fail
WHERE batch_id = 10001
LIMIT 1000000, 5000;
```

这类 SQL 的问题是：数据库需要先跳过前 1000000 行，再返回后 5000 行。页码越深，跳过的数据越多，性能越差。

对于导出任务来说，我们不关心“第几页”，只关心“从上次处理到的位置继续向后处理”，所以更适合游标分页。

## 4. 游标分页核心代码

第 20 小节中失败记录查询方法：

```java
private List<CouponTaskFailDO> listUserCouponTaskFail(Long batchId, Long maxId) {
    LambdaQueryWrapper<CouponTaskFailDO> queryWrapper = Wrappers.lambdaQuery(CouponTaskFailDO.class)
            .eq(CouponTaskFailDO::getBatchId, batchId)
            .gt(CouponTaskFailDO::getId, maxId)
            .last("LIMIT " + BATCH_USER_COUPON_SIZE);
    return couponTaskFailMapper.selectList(queryWrapper);
}
```

等价 SQL：

```sql
SELECT *
FROM t_coupon_task_fail
WHERE batch_id = #{batchId}
  AND id > #{maxId}
LIMIT 5000;
```

字段解释：

- `batchId`：只查询当前任务批次的失败记录。
- `maxId`：上一批已处理的最大主键 ID。
- `LIMIT 5000`：单批最多处理 5000 条。

## 5. 失败 Excel 分批写出

任务结束时生成失败 Excel：

```java
long initId = 0;
boolean isFirstIteration = true;
String failFileAddress = excelPath + "/用户分发记录失败Excel-" + event.getCouponTaskBatchId() + ".xlsx";

try (ExcelWriter excelWriter = EasyExcel.write(failFileAddress, UserCouponTaskFailExcelObject.class).build()) {
    WriteSheet writeSheet = EasyExcel.writerSheet("用户分发失败Sheet").build();
    while (true) {
        List<CouponTaskFailDO> couponTaskFailDOList = listUserCouponTaskFail(event.getCouponTaskBatchId(), initId);
        if (CollUtil.isEmpty(couponTaskFailDOList)) {
            if (isFirstIteration) {
                failFileAddress = null;
            }
            break;
        }

        isFirstIteration = false;

        List<UserCouponTaskFailExcelObject> excelDataList = couponTaskFailDOList.stream()
                .map(each -> JSONObject.parseObject(each.getJsonObject(), UserCouponTaskFailExcelObject.class))
                .toList();
        excelWriter.write(excelDataList, writeSheet);

        if (couponTaskFailDOList.size() < BATCH_USER_COUPON_SIZE) {
            break;
        }

        initId = couponTaskFailDOList.stream()
                .mapToLong(CouponTaskFailDO::getId)
                .max()
                .orElse(initId);
    }
}
```

流程：

1. `initId = 0`，从最开始查。
2. 查询 `id > initId` 的下一批失败记录。
3. 如果第一批就是空，说明没有失败记录，`failFileAddress = null`。
4. 如果有失败记录，转换成 Excel 行对象。
5. 写入当前 Sheet。
6. 如果本批不足 5000 条，说明后面没有更多数据。
7. 如果本批等于 5000 条，更新 `initId` 为本批最大 ID，继续下一轮。

## 6. 为什么不使用页码分页

页码分页示例：

```java
int pageNo = 1;
int pageSize = 5000;
while (true) {
    List<CouponTaskFailDO> list = mapper.selectPage(pageNo, pageSize);
    pageNo++;
}
```

问题：

- 页码越大，数据库跳过的数据越多。
- 如果导出过程中有新数据插入，页码分页可能出现重复或遗漏。
- 失败记录导出只需要顺序扫描，不需要随机跳页。

游标分页更适合这种“从头扫到尾”的导出场景。

## 7. 索引设计建议

本节 SQL 条件是：

```sql
WHERE batch_id = ?
  AND id > ?
LIMIT 5000
```

建议索引：

```sql
CREATE INDEX idx_batch_id_id ON t_coupon_task_fail(batch_id, id);
```

索引含义：

- 先按 `batch_id` 定位当前任务批次。
- 再按 `id > maxId` 顺序向后扫描。

如果只有 `batch_id` 索引，数据库仍可能需要在该批次内做额外扫描；联合索引更贴合查询条件。

## 8. Spring Boot 与框架语法补充

### 8.1 `while (true)` 与 `break`

```java
while (true) {
    List<Data> list = query();
    if (list.isEmpty()) {
        break;
    }
    handle(list);
}
```

这是典型“不知道要循环多少次”的写法。只要还有数据就继续，没有数据就退出。

### 8.2 `try-with-resources`

```java
try (ExcelWriter excelWriter = EasyExcel.write(path, Row.class).build()) {
    excelWriter.write(data, sheet);
}
```

`try (...)` 中的对象会在代码块结束后自动关闭，适合文件、网络连接、流等资源。

### 8.3 `stream().map().toList()`

```java
List<UserCouponTaskFailExcelObject> excelDataList = failList.stream()
        .map(each -> JSONObject.parseObject(each.getJsonObject(), UserCouponTaskFailExcelObject.class))
        .toList();
```

含义：

- 遍历失败记录。
- 把每条 JSON 转成 Excel 行对象。
- 收集成 List。

### 8.4 `.last("LIMIT " + size)`

MyBatis-Plus 的 `.last()` 会把内容拼到 SQL 末尾。

```java
Wrappers.lambdaQuery(UserDO.class)
        .gt(UserDO::getId, maxId)
        .last("LIMIT 100");
```

注意：`.last()` 直接拼 SQL，不能拼接用户输入，避免 SQL 注入。本节 `BATCH_USER_COUPON_SIZE` 是后端常量，风险可控。

## 10. 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 失败文件地址为空 | 没有失败记录 | 查询 `t_coupon_task_fail` |
| 导出很慢 | 缺少 `(batch_id, id)` 索引 | 增加联合索引 |
| 导出内存高 | 单批过大 | 调小批次大小 |
| 重复导出同一批数据 | `initId` 未更新 | 检查最大 ID 更新逻辑 |
