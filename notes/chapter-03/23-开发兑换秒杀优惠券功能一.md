# 第 23 小节：开发兑换/秒杀优惠券功能（一）

## 新手先读

本节进入用户主动领券和秒杀场景。普通领券可以理解成用户点击领取一张券；秒杀领券则是大量用户在短时间内同时抢同一批券。

阅读时重点关注两道防线：Redis Lua 先快速判断库存和限领，MySQL 事务再做最终落库和库存兜底。不要只看接口返回成功，还要看用户券记录、库存和缓存是否一致。

## 2. 教程核心内容提炼

批量分发是商家后台发券，用户被动获得优惠券。兑换/秒杀是用户主动抢券，高并发风险更高。

本节第一版流程：

1. 用户调用兑换接口。
2. 查询优惠券模板缓存，确认模板存在。
3. 校验当前时间是否在可领取时间范围。
4. 读取领取规则中的单人限领次数。
5. 执行 Redis Lua，原子校验库存、限领次数，并扣减 Redis 库存。
6. 开启数据库事务。
7. 扣减 MySQL 模板库存。
8. 插入用户优惠券记录。
9. 写入用户优惠券列表缓存。
10. 发送用户券到期延时消息。

这是一版同步兑换流程：接口等待数据库和缓存都处理完成后返回。

## 4. 用户兑换接口

## 5. Redis Lua 脚本

`stock_decrement_and_save_user_receive.lua`：

```lua
local function combineFields(firstField, secondField)
    local SECOND_FIELD_BITS = 14
    local firstFieldValue = firstField
    local shiftedFirstField = firstFieldValue * (2 ^ SECOND_FIELD_BITS)
    return shiftedFirstField + secondField
end

local stock = tonumber(redis.call('HGET', KEYS[1], 'stock'))

if stock <= 0 then
    return combineFields(1, 0)
end

local userCouponCount = tonumber(redis.call('GET', KEYS[2]))

if userCouponCount == nil then
    userCouponCount = 0
end

if userCouponCount >= tonumber(ARGV[2]) then
    return combineFields(2, userCouponCount)
end

if userCouponCount == 0 then
    redis.call('SET', KEYS[2], 1)
    redis.call('EXPIRE', KEYS[2], ARGV[1])
else
    redis.call('INCR', KEYS[2])
end

redis.call('HINCRBY', KEYS[1], 'stock', -1)

return combineFields(0, userCouponCount + 1)
```

脚本返回值包含两个字段：

- 第一字段：错误类型。`0` 成功，`1` 库存不足，`2` 达到限领。
- 第二字段：用户当前领取次数。

为什么用 Lua？

- Redis 内部单线程执行脚本。
- 库存判断、限领判断、次数增加、库存扣减在一个脚本中完成。
- 避免高并发下多个请求同时通过校验。

```java
Long stockDecrementLuaResult = stringRedisTemplate.execute(
```

这里先做缓存层的高并发保护：

## 7. 编程式事务落库

本节使用 `TransactionTemplate`：

```java
transactionTemplate.executeWithoutResult(status -> {
    try {
        int decremented = couponTemplateMapper.decrementCouponTemplateStock(
                Long.parseLong(requestParam.getShopNumber()),
                Long.parseLong(requestParam.getCouponTemplateId()),
                1L
        );
        if (!SqlHelper.retBool(decremented)) {
            throw new ServiceException("优惠券已被领取完啦");
        }

        UserCouponDO userCouponDO = UserCouponDO.builder()
                .couponTemplateId(Long.parseLong(requestParam.getCouponTemplateId()))
                .userId(Long.parseLong(UserContext.getUserId()))
                .source(requestParam.getSource())
                .receiveCount(Long.valueOf(extractSecondField).intValue())
                .status(0)
                .receiveTime(now)
                .validStartTime(now)
                .validEndTime(validEndTime)
                .build();
        userCouponMapper.insert(userCouponDO);
    } catch (Exception ex) {
        status.setRollbackOnly();
        throw new ServiceException("优惠券领取异常，请稍候再试");
    }
});
```

为什么使用事务？

扣数据库库存和插入用户券必须一起成功或一起失败。否则可能出现库存扣了但用户没有券，或者用户有券但库存没扣。

## 8. 用户券缓存写入

同步写缓存：

```java
String userCouponListCacheKey = String.format(EngineRedisConstant.USER_COUPON_TEMPLATE_LIST_KEY, UserContext.getUserId());
String userCouponItemCacheKey = StrUtil.builder()
        .append(requestParam.getCouponTemplateId())
        .append("_")
        .append(userCouponDO.getId())
        .toString();
stringRedisTemplate.opsForZSet().add(userCouponListCacheKey, userCouponItemCacheKey, now.getTime());
```

然后做写后查询：

```java
Double scored = stringRedisTemplate.opsForZSet().score(userCouponListCacheKey, userCouponItemCacheKey);
if (scored == null) {
    stringRedisTemplate.opsForZSet().add(userCouponListCacheKey, userCouponItemCacheKey, now.getTime());
}
```

这是为了尽量降低 Redis 主从复制、持久化极端情况下的数据丢失风险。

## 9. 用户券到期延时关闭

用户券有效期结束后，需要：

- 从用户券列表缓存中移除。
- 把数据库用户券状态改为已过期。

发送延时消息：

```java
UserCouponDelayCloseEvent userCouponDelayCloseEvent = UserCouponDelayCloseEvent.builder()
        .couponTemplateId(requestParam.getCouponTemplateId())
        .userCouponId(String.valueOf(userCouponDO.getId()))
        .userId(UserContext.getUserId())
        .delayTime(validEndTime.getTime())
        .build();
couponDelayCloseProducer.sendMessage(userCouponDelayCloseEvent);
```

消费者 `UserCouponDelayCloseConsumer` 到期后处理：

```java
stringRedisTemplate.opsForZSet().remove(userCouponListCacheKey, userCouponItemCacheKey);

LambdaUpdateWrapper<UserCouponDO> updateWrapper = Wrappers.lambdaUpdate(UserCouponDO.class)
        .eq(UserCouponDO::getId, event.getUserCouponId())
        .eq(UserCouponDO::getUserId, event.getUserId())
        .eq(UserCouponDO::getStatus, UserCouponStatusEnum.UNUSED.getCode())
```

## 10. direct 与 binlog 缓存策略

配置项：

```yaml
one-coupon:
  user-coupon-list:
    save-cache:
      type: direct
```

两种模式：

| 模式 | 含义 |
| --- | --- |
| `direct` | 业务流程中直接写 Redis |
| `binlog` | 监听数据库 Binlog，再异步写 Redis |

本节默认 direct 更直观。`CanalBinlogSyncUserCouponConsumer` 则为 binlog 模式准备。

## 11. Spring Boot 与框架语法补充

### 11.1 `TransactionTemplate`

编程式事务示例：

```java
transactionTemplate.executeWithoutResult(status -> {
    try {
        mapper.insert(data);
    } catch (Exception ex) {
        status.setRollbackOnly();

```

相比 `@Transactional`，它可以把事务范围写得更明确。

### 11.2 `DuplicateKeyException`

数据库唯一索引冲突时，Spring 可能抛出：

```java

```

本节用它识别用户重复领取。

### 11.3 `@Value`

```java
@Value("${one-coupon.user-coupon-list.save-cache.type:direct}")
```

表示从配置读取值，如果没配置则使用 `direct`。

### 11.4 `DateUtil.isIn`

## 13. 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 提示不在领取时间 | 模板开始或结束时间不匹配 | 检查模板有效期 |
| 提示库存不足 | Redis 模板库存为 0 | 检查缓存和数据库库存 |
| 提示重复领取 | 唯一索引或限领 Key 生效 | 换用户或调整规则 |
| 用户券缓存没有数据 | `direct` 写缓存失败 | 查看 Redis 和日志 |
