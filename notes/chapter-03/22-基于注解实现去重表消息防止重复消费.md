# 第 22 小节：基于注解实现去重表消息防止重复消费

## 新手先读

本节的核心问题是 MQ 消息可能重复投递。不要把“消息队列可靠”误解成“业务只会执行一次”，RocketMQ 更常见的语义是至少投递一次，因此消费端必须自己防重复。

阅读时先看注解怎么标记一个消费者方法，再看切面如何在方法执行前判断消息是否已经处理过。Redis 是快速挡板，去重表是持久记录，两者配合降低重复消费风险。

## 2. 教程核心内容提炼

消息队列通常只能提供“至少一次”投递。也就是说，一条消息可能被消费一次，也可能因为超时、异常、重平衡等原因被重复投递。

优惠券分发任务不能重复执行，因为重复执行可能导致：

- 重复扣库存。
- 重复写用户券。
- 重复生成失败记录。
- 任务状态被重复推进。

本节新增通用注解：

```java
@NoMQDuplicateConsume
```

业务消费者只需要在 `onMessage` 上加注解，框架层负责 Redis 幂等 Key 的创建、状态更新和异常回滚。

## 5. 注解定义

`NoMQDuplicateConsume`：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NoMQDuplicateConsume {

    String keyPrefix() default "";

    String key();

    long keyTimeout() default 3600L;
}
```

字段解释：

| 字段 | 含义 |
| --- | --- |
| `keyPrefix` | Redis 幂等 Key 前缀 |
| `key` | 业务唯一键，支持 SpEL |
| `keyTimeout` | 幂等 Key 过期时间，单位秒 |

这个注解只能加在方法上，因为 `@Target(ElementType.METHOD)`。

## 6. 消费状态枚举

`IdempotentMQConsumeStatusEnum`：

```java
@RequiredArgsConstructor
public enum IdempotentMQConsumeStatusEnum {

    CONSUMING("0"),

    CONSUMED("1");

    @Getter
    private final String code;

    public static boolean isError(String consumeStatus) {
        return Objects.equals(CONSUMING.code, consumeStatus);
    }
}
```

状态含义：

- `CONSUMING = 0`：消息正在被某个消费者处理。
- `CONSUMED = 1`：消息已经成功处理。

如果重复消息发现状态是 `CONSUMING`，说明前一次消费可能还没结束，需要让 MQ 稍后重试。

如果重复消息发现状态是 `CONSUMED`，说明已经处理成功，直接忽略即可。

## 7. AOP 切面核心逻辑

`NoMQDuplicateConsumeAspect`：

```java
@Slf4j
@Aspect
@RequiredArgsConstructor
public final class NoMQDuplicateConsumeAspect {

    private final StringRedisTemplate stringRedisTemplate;

    private static final String LUA_SCRIPT = """
            local key = KEYS[1]
            local value = ARGV[1]
            local expire_time_ms = ARGV[2]
            return redis.call('SET', key, value, 'NX', 'GET', 'PX', expire_time_ms)
            """;

    @Around("@annotation(com.nageoffer.onecoupon.framework.idempotent.NoMQDuplicateConsume)")
    public Object noMQRepeatConsume(ProceedingJoinPoint joinPoint) throws Throwable {
        NoMQDuplicateConsume annotation = getNoMQDuplicateConsumeAnnotation(joinPoint);
        String uniqueKey = annotation.keyPrefix()
                + SpELUtil.parseKey(annotation.key(), ((MethodSignature) joinPoint.getSignature()).getMethod(), joinPoint.getArgs());

        String absentAndGet = stringRedisTemplate.execute(
                RedisScript.of(LUA_SCRIPT, String.class),
                List.of(uniqueKey),
                IdempotentMQConsumeStatusEnum.CONSUMING.getCode(),
                String.valueOf(TimeUnit.SECONDS.toMillis(annotation.keyTimeout()))
        );

        if (Objects.nonNull(absentAndGet)) {
            boolean errorFlag = IdempotentMQConsumeStatusEnum.isError(absentAndGet);
            if (errorFlag) {
                throw new ServiceException(String.format("消息消费者幂等异常，幂等标识：%s", uniqueKey));
            }
            return null;
        }

        Object result;
        try {
            result = joinPoint.proceed();
            stringRedisTemplate.opsForValue().set(uniqueKey, IdempotentMQConsumeStatusEnum.CONSUMED.getCode(), annotation.keyTimeout(), TimeUnit.SECONDS);
        } catch (Throwable ex) {
            stringRedisTemplate.delete(uniqueKey);
            throw ex;
        }
        return result;
    }
}
```

处理流程：

1. 解析注解。
2. 拼接 Redis 幂等 Key。
3. 用 Lua 设置 `CONSUMING` 状态。
4. 如果 Key 已存在，根据旧状态决定返回或抛异常。
5. 如果 Key 不存在，执行原消费方法。
6. 消费成功后把状态改为 `CONSUMED`。
7. 消费失败则删除 Key，让 MQ 后续可以重试。

## 8. Redis SET NX PX GET

Lua 中：

```lua
return redis.call('SET', key, value, 'NX', 'GET', 'PX', expire_time_ms)
```

参数含义：

- `SET key value`：设置 Key。
- `NX`：只有 Key 不存在时才设置。
- `GET`：返回旧值。
- `PX expire_time_ms`：设置毫秒级过期时间。

效果：

| 场景 | 返回值 | 说明 |
| --- | --- | --- |
| Key 不存在 | `null` | 成功设置为消费中 |
| Key 已存在，值是 `0` | `0` | 已有消费者正在处理 |
| Key 已存在，值是 `1` | `1` | 已经消费成功 |

## 9. SpEL 解析业务 Key

注解中：

```java
key = "#messageWrapper.message.couponTaskId"
```

`SpELUtil` 会把它解析成真实任务 ID：

```java
public static Object parse(String spEl, Method method, Object[] contextObj) {
    DefaultParameterNameDiscoverer discoverer = new DefaultParameterNameDiscoverer();
    ExpressionParser parser = new SpelExpressionParser();
    Expression exp = parser.parseExpression(spEl);
    String[] params = discoverer.getParameterNames(method);
    StandardEvaluationContext context = new StandardEvaluationContext();
    if (ArrayUtil.isNotEmpty(params)) {
        for (int len = 0; len < params.length; len++) {
            context.setVariable(params[len], contextObj[len]);
        }
    }
    return exp.getValue(context);
}
```

简单示例：

```java
public void onMessage(MessageWrapper<CouponTaskExecuteEvent> messageWrapper) {
}
```

SpEL：

```text
#messageWrapper.message.couponTaskId
```

就是从方法参数 `messageWrapper` 中取 `message`，再取 `couponTaskId`。

## 10. Spring Boot 与框架语法补充

### 10.1 `@Aspect`

`@Aspect` 表示当前类是切面类。

```java
@Aspect
@Component
public class DemoAspect {
}
```

切面可以在目标方法执行前后插入通用逻辑。

### 10.2 `@Around`

```java
@Around("@annotation(com.example.Demo)")
public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
    System.out.println("before");
    Object result = joinPoint.proceed();
    System.out.println("after");
    return result;
}
```

`@Around` 可以决定是否执行原方法，也可以在原方法前后做处理。

### 10.3 `ProceedingJoinPoint`

`ProceedingJoinPoint` 代表被拦截的方法。

```java
Object result = joinPoint.proceed();
```

这行代码表示继续执行原方法。如果不调用，原方法就不会执行。

### 10.4 `MethodSignature`

```java
MethodSignature signature = (MethodSignature) joinPoint.getSignature();
Method method = signature.getMethod();
```

用于获取被拦截方法的反射信息，比如方法名、参数类型、注解。

### 10.5 Java 文本块

```java
private static final String LUA_SCRIPT = """
        local key = KEYS[1]
        return redis.call('GET', key)
        """;
```

三引号文本块适合写多行字符串，常用于 SQL、JSON、Lua 脚本。

### 11.5 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 注解不生效 | AOP 自动配置未加载 | 检查 `IdempotentConfiguration` |
| SpEL 解析失败 | 参数名不匹配或编译参数缺失 | 检查方法参数名和表达式 |
| 消费失败后无法重试 | 幂等 Key 没删除 | 检查 catch 分支 |
| 重复消息仍执行 | Key 前缀或业务 Key 不唯一 | 检查注解配置 |
