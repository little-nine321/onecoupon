# 第 27 小节：用户查询/取消优惠券预约提醒功能

## 新手先读

本节补齐预约提醒的查询和取消。新手先理解一个关键点：延时消息一旦发出，通常不能简单撤回，所以用户取消预约后，消费者到点时还要再次检查预约状态。

取消逻辑里的布隆过滤器和缓存一致性，都是为了让系统快速判断某条预约是否还有效，同时避免取消后仍然误发提醒。

## 2. 教程核心内容提炼

第 25、26 小节已经支持创建预约和发送提醒。本节解决两个用户侧问题：

- 用户需要查看自己预约了哪些优惠券提醒。
- 用户需要在开抢前取消某个提醒。

难点在于：提醒创建后，RocketMQ 延时消息已经发出，取消预约不能真正删除 MQ 中的延时消息。因此本节采用“取消标记”方案：

1. 用户取消预约时，更新数据库 bitmap。
2. 把取消信息写入布隆过滤器。
3. 消息到期消费时，先判断该提醒是否已取消。
4. 如果已取消，不发送提醒。

## 4. Controller 接口

@Operation(summary = "查询优惠券预约提醒")

@Operation(summary = "取消优惠券预约提醒")

- 提醒方式。
- 提前提醒时间。

## 5. 查询预约提醒

`listCouponRemind`：

```java
public List<CouponTemplateRemindQueryRespDTO> listCouponRemind(CouponTemplateRemindQueryReqDTO requestParam) {
    String value = stringRedisTemplate.opsForValue().get(
            String.format(USER_COUPON_TEMPLATE_REMIND_INFORMATION, requestParam.getUserId())
    );
    if (value != null) {
        return JSON.parseArray(value, CouponTemplateRemindQueryRespDTO.class);
    }

    LambdaQueryWrapper<CouponTemplateRemindDO> queryWrapper = Wrappers.lambdaQuery(CouponTemplateRemindDO.class)
            .eq(CouponTemplateRemindDO::getUserId, requestParam.getUserId());
    List<CouponTemplateRemindDO> remindList = couponTemplateRemindMapper.selectList(queryWrapper);
    if (CollUtil.isEmpty(remindList)) {
        return new ArrayList<>();
    }

    List<Long> couponIds = remindList.stream().map(CouponTemplateRemindDO::getCouponTemplateId).toList();
    List<Long> shopNumbers = remindList.stream().map(CouponTemplateRemindDO::getShopNumber).toList();
    List<CouponTemplateDO> couponTemplateDOList = couponTemplateService.listCouponTemplateByIds(couponIds, shopNumbers);
    List<CouponTemplateRemindQueryRespDTO> actualResult = BeanUtil.copyToList(couponTemplateDOList, CouponTemplateRemindQueryRespDTO.class);

    actualResult.forEach(each -> {
        remindList.stream()
                .filter(i -> i.getCouponTemplateId().equals(each.getId()))
                .findFirst()
                .ifPresent(i -> CouponTemplateRemindUtil.fillRemindInformation(each, i.getInformation()));
    });

    stringRedisTemplate.opsForValue().set(
            String.format(USER_COUPON_TEMPLATE_REMIND_INFORMATION, requestParam.getUserId()),
            JSON.toJSONString(actualResult),
            1,
            TimeUnit.MINUTES
    );
    return actualResult;
}
```

查询流程：

1. 先查用户预约提醒缓存。
2. 缓存命中直接返回。
3. 缓存未命中查预约表。
4. 根据模板 ID 和店铺编号批量查优惠券模板。
5. 把 bitmap 解析成可读提醒信息。
6. 结果写入 Redis，TTL 1 分钟。

## 6. 取消预约提醒

`cancelCouponRemind` 核心逻辑：

```java
Long bitMap = CouponTemplateRemindUtil.calculateBitMap(requestParam.getRemindTime(), requestParam.getType());
if ((bitMap & couponTemplateRemindDO.getInformation()) == 0L) {
    throw new ClientException("您没有预约该时间点的提醒");
}

bitMap ^= couponTemplateRemindDO.getInformation();
queryWrapper.eq(CouponTemplateRemindDO::getInformation, couponTemplateRemindDO.getInformation());
if (bitMap.equals(0L)) {
    if (couponTemplateRemindMapper.delete(queryWrapper) == 0) {
        throw new ClientException("取消提醒失败，请刷新页面后重试");
    }
} else {
    couponTemplateRemindDO.setInformation(bitMap);
    if (couponTemplateRemindMapper.update(couponTemplateRemindDO, queryWrapper) == 0) {
        throw new ClientException("取消提醒失败，请刷新页面后重试");
    }
}
```

处理逻辑：

- 如果目标 bit 不存在，说明用户没预约该提醒。
- 如果取消后 `information = 0`，说明没有任何提醒了，删除记录。
- 如果还有其他提醒，更新 `information`。
- 更新条件中带旧 `information`，用于防止并发修改覆盖。

## 7. 取消布隆过滤器

取消后写入布隆过滤器：

```java
cancelRemindBloomFilter.add(String.valueOf(
        Objects.hash(
                requestParam.getCouponTemplateId(),
                UserContext.getUserId(),
                requestParam.getRemindTime(),
                requestParam.getType()
        )
));
```

提醒执行前判断：

```java
public boolean isCancelRemind(CouponTemplateRemindDTO requestParam) {
    if (!cancelRemindBloomFilter.contains(String.valueOf(Objects.hash(
            requestParam.getCouponTemplateId(),
            requestParam.getUserId(),
            requestParam.getRemindTime(),
            requestParam.getType()
    )))) {
        return false;
    }

    // 可能是布隆过滤器误判，再查数据库确认
    CouponTemplateRemindDO remindDO = couponTemplateRemindMapper.selectOne(queryWrapper);
    if (remindDO == null) {
        return true;
    }

    Long information = remindDO.getInformation();
    Long bitMap = CouponTemplateRemindUtil.calculateBitMap(requestParam.getRemindTime(), requestParam.getType());
    return (bitMap & information) == 0L;
}
```

布隆过滤器的作用是快速挡住大部分“未取消”的提醒，无需每条提醒消息都查数据库。

## 8. 缓存一致性策略

创建或取消预约后都执行：

```java
stringRedisTemplate.delete(String.format(USER_COUPON_TEMPLATE_REMIND_INFORMATION, UserContext.getUserId()));
```

这是典型的“更新数据库后删除缓存”策略。

为什么不是更新缓存？

- 查询结果由预约记录和模板信息组合而来。
- 更新缓存容易漏字段或产生不一致。
- 删除缓存简单可靠，下次查询重新构建。

## 9. Spring Boot 与框架语法补充

### 9.1 `Objects.hash`

```java
int hash = Objects.hash(couponTemplateId, userId, remindTime, type);
```

把多个字段组合成一个哈希值。本节用它作为取消提醒布隆过滤器的元素。

### 9.2 乐观更新

```java
queryWrapper.eq(CouponTemplateRemindDO::getInformation, oldInformation);
int updated = mapper.update(entity, queryWrapper);
```

只有数据库里的 `information` 仍等于旧值时才更新成功。如果并发修改过，更新返回 0，提示用户刷新重试。

### 9.3 `BeanUtil.copyToList`

```java
List<RespDTO> result = BeanUtil.copyToList(entityList, RespDTO.class);
```

把实体列表转换成响应 DTO 列表，避免手写循环拷贝。

## 11. 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 取消提示未预约 | 目标 bit 不存在 | 检查 type 和 remindTime |
| 取消失败刷新重试 | 并发修改导致乐观更新失败 | 重新查询后再取消 |
| 查询结果旧 | 缓存未删除 | 检查创建/取消后的 delete |
| 取消后仍提醒 | 消费端未调用取消判断 | 检查提醒执行器逻辑 |
