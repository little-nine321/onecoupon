# 第 16 小节：用户查询优惠券之缓存击穿

## 新手先读

本节开始进入 `engine` 服务，也就是用户侧领券、查券、用券相关能力。缓存击穿可以先理解成：一个非常热门的优惠券模板缓存突然失效，大量请求同时去查数据库，数据库可能被压垮。

## 2. 教程核心内容提炼

后台管理服务负责商家创建、管理优惠券模板；引擎服务更靠近用户侧高频请求，比如查询可领取券、领取券、核销券等。

本节新增 `engine` 服务中的优惠券模板查询能力：

1. 用户请求查询模板。
2. 先查 Redis 缓存。
3. 缓存命中，直接返回。
4. 缓存未命中，获取分布式锁。
5. 获取锁后再次查缓存。
6. 如果仍然没有缓存，再查数据库。
7. 查询成功后写入 Redis Hash，并设置过期时间为模板有效期结束时间。
8. 返回模板信息。

这套流程用于解决缓存击穿：某个热点 Key 过期后，大量请求同时打到数据库。

## 4. engine 服务定位

可以把服务职责简单分成两类：

| 服务 | 主要使用者 | 职责 |

## 7. Service 查询核心逻辑

`CouponTemplateServiceImpl#findCouponTemplate`：

```java
@Override
public CouponTemplateQueryRespDTO findCouponTemplate(CouponTemplateQueryReqDTO requestParam) {
    String couponTemplateCacheKey = String.format(EngineRedisConstant.COUPON_TEMPLATE_KEY, requestParam.getCouponTemplateId());
    Map<Object, Object> couponTemplateCacheMap = stringRedisTemplate.opsForHash().entries(couponTemplateCacheKey);

    if (MapUtil.isEmpty(couponTemplateCacheMap)) {
        RLock lock = redissonClient.getLock(String.format(EngineRedisConstant.LOCK_COUPON_TEMPLATE_KEY, requestParam.getCouponTemplateId()));
        lock.lock();

        try {
            couponTemplateCacheMap = stringRedisTemplate.opsForHash().entries(couponTemplateCacheKey);
            if (MapUtil.isEmpty(couponTemplateCacheMap)) {
                LambdaQueryWrapper<CouponTemplateDO> queryWrapper = Wrappers.lambdaQuery(CouponTemplateDO.class)
                        .eq(CouponTemplateDO::getShopNumber, Long.parseLong(requestParam.getShopNumber()))
                        .eq(CouponTemplateDO::getId, Long.parseLong(requestParam.getCouponTemplateId()))
                        .eq(CouponTemplateDO::getStatus, CouponTemplateStatusEnum.ACTIVE.getStatus());
                CouponTemplateDO couponTemplateDO = couponTemplateMapper.selectOne(queryWrapper);

                if (couponTemplateDO == null) {
                    throw new ClientException("优惠券模板不存在或已过期");
                }

                CouponTemplateQueryRespDTO actualRespDTO = BeanUtil.toBean(couponTemplateDO, CouponTemplateQueryRespDTO.class);
                Map<String, Object> cacheTargetMap = BeanUtil.beanToMap(actualRespDTO, false, true);
                Map<String, String> actualCacheTargetMap = cacheTargetMap.entrySet().stream()
                        .collect(Collectors.toMap(
                                Map.Entry::getKey,
                                entry -> entry.getValue() != null ? entry.getValue().toString() : ""
                        ));

                String luaScript = "redis.call('HMSET', KEYS[1], unpack(ARGV, 1, #ARGV - 1)) " +
                        "redis.call('EXPIREAT', KEYS[1], ARGV[#ARGV])";

                List<String> keys = Collections.singletonList(couponTemplateCacheKey);
                List<String> args = new ArrayList<>(actualCacheTargetMap.size() * 2 + 1);
                actualCacheTargetMap.forEach((key, value) -> {
                    args.add(key);
                    args.add(value);
                });

                args.add(String.valueOf(couponTemplateDO.getValidEndTime().getTime() / 1000));

                stringRedisTemplate.execute(
                        new DefaultRedisScript<>(luaScript, Long.class),
                        keys,
                        args.toArray()
                );
                couponTemplateCacheMap = cacheTargetMap.entrySet()
                        .stream()
                        .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue));
            }
        } finally {
            lock.unlock();
        }
    }

    return BeanUtil.mapToBean(couponTemplateCacheMap, CouponTemplateQueryRespDTO.class, false, CopyOptions.create());
}
```

## 8. 双重判定锁

本节最重要的结构是：

```java
Map<Object, Object> cache = redis.entries(key);

if (cache is empty) {
    lock.lock();
    try {
        cache = redis.entries(key);
        if (cache is empty) {
            data = queryDatabase();
            writeRedis(data);
        }
    } finally {
        lock.unlock();
    }
}
```

为什么要查两次缓存？

假设 1000 个请求同时发现缓存为空。第一个请求拿到锁并查询数据库，写入 Redis。其他请求等待锁。等第二个请求拿到锁时，如果不再次查缓存，它还会继续查询数据库，锁就失去了大部分意义。

第二次查缓存的作用是：让等待锁的请求发现缓存已经被前一个请求重建，从而直接使用缓存。

## 9. Lua 脚本写缓存

本节使用 Lua 一次性完成两个操作：

```java
String luaScript = "redis.call('HMSET', KEYS[1], unpack(ARGV, 1, #ARGV - 1)) " +
        "redis.call('EXPIREAT', KEYS[1], ARGV[#ARGV])";
```

逻辑：

- `HMSET`：把模板字段写入 Redis Hash。
- `EXPIREAT`：设置 Key 在模板有效期结束时过期。

为什么不用两条 Java 命令？

```java
redis.opsForHash().putAll(key, map);
redis.expireAt(key, validEndTime);
```

这样也能实现，但中间如果应用宕机，可能出现“写了缓存但没设置过期时间”的问题。Lua 脚本在 Redis 内部一次执行，能降低这种中间状态风险。

参数构造：

```java
List<String> args = new ArrayList<>(actualCacheTargetMap.size() * 2 + 1);
actualCacheTargetMap.forEach((key, value) -> {
    args.add(key);
    args.add(value);
});
args.add(String.valueOf(couponTemplateDO.getValidEndTime().getTime() / 1000));
```

`args` 的结构是：

```text
field1, value1, field2, value2, field3, value3, expireTimestamp
```

Lua 中 `ARGV[#ARGV]` 取最后一个参数，也就是过期时间戳。

## 10. ShardingSphere 配置

`engine` 服务新增 `shardingsphere-config.yaml`，配置 `t_coupon_template` 分库分表：

```yaml
dataSources:
  ds_0:
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/one_coupon_rebuild_0
  ds_1:
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/one_coupon_rebuild_1

rules:
  - !SHARDING
    tables:
      t_coupon_template:
        actualDataNodes: ds_${0..1}.t_coupon_template_${0..15}
        databaseStrategy:
          standard:
            shardingColumn: shop_number
            shardingAlgorithmName: coupon_template_database_mod
        tableStrategy:
          standard:
            shardingColumn: shop_number
            shardingAlgorithmName: coupon_template_table_mod
```

查询条件中必须带 `shop_number`：

```java
.eq(CouponTemplateDO::getShopNumber, Long.parseLong(requestParam.getShopNumber()))
```

这样 ShardingSphere 才能根据分片键路由到具体库表，避免全库全表扫描。

## 12. Spring Boot 与框架语法补充

### 12.1 `StringRedisTemplate.opsForHash()`

Redis Hash 类似 Java 中的 Map。

```java
stringRedisTemplate.opsForHash().put("user:1", "name", "张三");
stringRedisTemplate.opsForHash().put("user:1", "age", "18");
Map<Object, Object> user = stringRedisTemplate.opsForHash().entries("user:1");
```

对应 Redis 数据结构：

```text
user:1
  name = 张三
  age = 18
```

### 12.2 `MapUtil.isEmpty`

Hutool 工具方法，用来判断 Map 是否为空。

```java
if (MapUtil.isEmpty(map)) {
    System.out.println("没有数据");
}
```

等价于：

```java
if (map == null || map.isEmpty()) {
    System.out.println("没有数据");
}
```

### 12.3 `RLock`

`RLock` 是 Redisson 的分布式锁。

```java
RLock lock = redissonClient.getLock("lock:template:1001");
lock.lock();
try {
    rebuildCache();
} finally {
    lock.unlock();
}
```

必须在 `finally` 中释放锁，避免业务异常导致锁不释放。

### 12.4 `BeanUtil.beanToMap`

把 Java 对象转换为 Map。

```java
UserDTO user = new UserDTO();
user.setName("张三");

Map<String, Object> map = BeanUtil.beanToMap(user, false, true);
```

本节用它把响应 DTO 转成 Redis Hash 字段。

### 12.5 Stream `Collectors.toMap`

把集合转换成 Map。

```java
Map<String, String> result = map.entrySet().stream()
        .collect(Collectors.toMap(
                Map.Entry::getKey,
                entry -> entry.getValue().toString()
        ));
```

本节用它把 `Map<String, Object>` 转成 `Map<String, String>`，方便写入 Redis。

### 12.6 `DefaultRedisScript`

`DefaultRedisScript` 用来执行 Redis Lua 脚本。

```java
String script = "return redis.call('GET', KEYS[1])";
String value = stringRedisTemplate.execute(
        new DefaultRedisScript<>(script, String.class),
        Collections.singletonList("demo:key")
);
```

第一个泛型参数表示脚本返回值类型。

### 12.7 `CopyOptions.create()`

Hutool `CopyOptions` 用于控制对象转换规则。

```java
UserDTO userDTO = BeanUtil.mapToBean(map, UserDTO.class, false, CopyOptions.create());
```

本节用它把 Redis Hash 读取出的 Map 转成响应 DTO。

### 13.8 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 查询报模板不存在 | `shopNumber`、模板 ID 或状态不匹配 | 检查分片库表数据 |
| 一直查不到缓存 | Redis 未启动或 Key 写入失败 | 检查 Redis 连接和日志 |
| TTL 是 -1 | 过期时间没有设置成功 | 检查 Lua 脚本执行 |
| ShardingSphere 全路由 | 查询条件缺少分片键 | 确认传入 `shopNumber` |
| 锁不释放 | 业务异常后未执行 finally | 检查 `lock.unlock()` |
